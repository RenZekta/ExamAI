# ExamAI

[English](README.md) | **Русский**

Веб-приложение в одном самодостаточном HTML-файле для подготовки к экзаменам. Оно предлагает два независимых режима обучения плюс конспект (Notebook) с режимом чтения, и всё это работает с банком вопросов в формате Markdown, который вы составляете сами (или делаете это с помощью ИИ):

1. **Тренировочный тест** — вопросы с выбором ответа, мгновенный вердикт, пояснение к каждому варианту и текущий счёт.
2. **Письменный экзамен** — ответы свободной формы, которые проверяет LLM, с потоковой выдачей отзыва, поддерживающим тоном и необязательным эталонным ответом для сравнения.
3. **Конспект** — весь импортированный банк, отрисованный как Markdown-заметки: каждая дисциплина, каждая тема и её ответ, в порядке импорта.

Никаких этапов сборки, зависимостей и сервера. Откройте `.html`-файл в браузере — и всё работает.

Интерфейс доступен на **английском и русском языках**: переключатель **🌐 Язык** расположен в верхней панели, выбор сохраняется в `localStorage`.

---

## Быстрый старт

1. Скачайте `ExamAI.html` (всё приложение — один файл).
2. Откройте его в любом современном браузере (Chrome, Firefox, Edge, Safari).
3. Нажмите **📥 Импорт вопросов и теста → 🧪 Загрузить встроенный пример**, чтобы попробовать демо-банк, или перетащите свой `.md`-файл в зону загрузки.
4. *(только для раздела 2)* нажмите **⚙️ API** и укажите адрес вашего LLM-эндпоинта (см. [Настройка API](#настройка-api)).

Всё. Импортированный банк сохраняется в `localStorage` и переживает перезагрузку страницы.

## Возможности

### Раздел 1 · Тренировочный тест

- Фильтрация по дисциплинам с отдельными чекбоксами (на каждом чипе видно, сколько вопросов теста и письменных тем он содержит).
- Выбор количества вопросов (поле **Вопросов**, до 200). Они случайным образом берутся из всех выбранных дисциплин и перемешиваются.
- Один клик показывает:
  - ✅/❌ вердикт,
  - общий разбор (если есть),
  - **полный список «Почему каждый вариант верный или неверный»** — каждый вариант со своим комментарием и подсветкой правильного/выбранного вами.
- Счётчик `Счёт: N/M` отображается в верхней панели.
- `↺ Сбросить ответы` очищает ваши выборы без перемешивания, чтобы можно было пройти тот же набор заново.

### Раздел 2 · Письменный экзамен (ИИ)

- **`🎲 Сгенерировать вопросы`** выбирает N случайных тем из *каждой* дисциплины (по умолчанию `1` на дисциплину). При трёх дисциплинах и `N = 1` вы получите три карточки — по одной на дисциплину.
- Каждая карточка содержит:
  - дословный вопрос экзамена,
  - сворачиваемый блок **📖 Показать эталонный ответ** (если эталон есть) с курсивной сноской: *«Только для справки — это конспект из учебника, а не ответ, который нужно воспроизвести слово в слово.»*,
  - поле для вашего ответа,
  - кнопку `Отправить на проверку ИИ`.
- При отправке карточка **раздваивается**: вопрос и ответ остаются слева, справа появляется отзыв ИИ.
- **Потоковая выдача** — отзыв рендерится токен за токеном с мигающим курсором, поэтому не нужно ждать полного ответа.
- Если сервер не поддерживает потоковую выдачу через SSE, приложение **автоматически переключается** на обычный запрос и показывает спиннер.
- Промпт для проверки заставляет модель быть **поддерживающим преподавателем**, а не бездушной машиной для выставления баллов, и относиться к эталону как к *конспекту учебника*, а не к чек-листу. Структура вывода:

  ```
  ## Оценка                 X/10 — вердикт в одно предложение
  ## Что верно               Конкретные верные положения
  ## Что неверно или неточно Мягкое объяснение заблуждений
  ## Что можно добавить      Необязательные дополнения
  ## Образцовый ответ        Эталонный ответ
  ## Совет                   Один дружеский совет
  ```

  (Заголовки локализуются вместе с интерфейсом: английская версия запрашивает `## Grade`, `## What's correct`, `## What's wrong or imprecise`, `## What could be added`, `## Model answer`, `## Tip`.)

- Каждую карточку можно отправить на проверку заново с новым ответом, независимо от остальных.

### Раздел 3 · Конспект

Режим чтения импортированного банка, оформленный как Markdown-документ:

```
# Название дисциплины

## 1. Дословная строка темы экзамена из вашего списка.
Импортированный эталонный ответ, отрисованный как настоящий Markdown.
…
```

- **Порядок импорта сохраняется точно** — дисциплины как заголовки `#`, темы каждой дисциплины как заголовки `## N.` с импортированным ответом под ними. Здесь ничего не перемешивается, не выбирается случайно и не оценивается.
- **Ответы отрисовываются как настоящий Markdown**, а не как простой текст: заголовки `#`–`######` (ATX) и setext, упорядоченные/неупорядоченные/вложенные списки, цитаты, таблицы GFM, блоки кода, правила `---`, `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `` `код` ``, ссылки и изображения. Ссылки/изображения ограничены протоколами `http(s)` и `mailto:`, а весь исходный текст сначала экранируется от HTML, поэтому враждебный `.md` не может внедрить разметку.
- **Вопросы теста и их варианты намеренно не показываются** — эта вкладка чисто учебные заметки (тема → ответ).
- **Поле фильтра** сужает дисциплины, темы и ответы и подсвечивает каждое совпадение; если совпадает сама дисциплина, все её темы остаются видимыми.
- **📋 Копировать как Markdown** кладёт текущий (отфильтрованный) вид в буфер обмена в виде Markdown `# … / ## N. …` — той же структуры, что рендерит вкладка.

### Верхняя панель

- Меню **📥 Импорт вопросов и теста**:
  - **Зона перетаскивания** — бросьте `.md`-файл в пунктирную область или нажмите на неё, чтобы открыть выбор файла.
  - **✏️ Вставить / изменить .md** — вставьте банк напрямую, без файла.
  - **📋 Скопировать промпт-шаблон** — копирует в буфер обмена полный системный промпт, по которому ИИ сможет составить совместимый `.md`-файл из сырого списка тем экзамена.
  - **🧪 Загрузить встроенный пример** — загружает демо-банк: три дисциплины с реальными темами экзаменов и эталонными ответами (встроенный пример написан на русском языке).
  - **🗑 Очистить импортированные данные** — стирает банк и `localStorage`.
  - Строка статуса под меню показывает, сколько дисциплин/вопросов/тем/эталонов загружено и у сколько вопросов теста есть комментарии к вариантам.

- Меню **⚙️ API** — адрес сервера, ключ API и необязательное имя модели. См. [Настройка API](#настройка-api).

- Меню **🌐 Язык** — переключение всего интерфейса между **English** и **Русский**. Выбор сохраняется в `localStorage` и применяется сразу: статусы, подсказки, кнопки, плейсхолдеры, а также промпт-шаблон и промпт проверки ответов. Тексты самого банка вопросов не переводятся — это ваши данные.

## Формат банка вопросов `.md`

У каждой дисциплины **два независимых списка** — `### Poll` (тест с выбором ответа) и `### Written` (дословные темы экзамена + эталонные ответы). Их длины не обязаны совпадать; обычно даже не должны.

```markdown
## Название дисциплины

### Poll
1. Что изучает эта дисциплина? - Неверный вариант {Почему этот вариант относится к другой области.} - *Верный вариант {Почему это именно правильный ответ, называя ключевой термин.} - Неверный вариант {Какое понятие на самом деле описывает этот вариант.} - Неверный вариант {Почему это инструмент, а не предмет.} // Ключевая мысль всего вопроса одним предложением.
2. Следующий вопрос? - ... - *... - ... - ... // ...

### Written
1. Дословная строка темы экзамена номер один.
> Краткий эталонный ответ, охватывающий ключевые моменты, термины
> и структуру, которые должны присутствовать в сильном ответе.
> Второй абзац эталонного ответа, если он нужен.
2. Дословная строка темы экзамена номер два.
> Его эталонный ответ на том же языке, что и строка темы.
```

### Правила

| Элемент | Синтаксис |
|---|---|
| Заголовок дисциплины | `## Название дисциплины` |
| Подсекция | `### Poll` и `### Written` (в этом порядке) |
| Вопрос теста | `N. Текст вопроса? - вариант - вариант - вариант - вариант` |
| Правильный вариант | Помечается `*` в начале |
| Комментарий к варианту | `{объясни, почему этот вариант верный или неверный}` после варианта |
| Общий разбор | `// ...` в конце строки теста (необязательно) |
| Тема письменного экзамена | `N. Дословная строка темы экзамена.` |
| Эталонный ответ | `> Строка эталонного ответа` на следующих строках. Один `>` = пустая строка. |

**Советы:**

- Поддерживаются многострочные вопросы теста: помещайте `- вариант` на отдельные строки (пример есть в [плейсхолдере модального окна вставки](#)). Фигурные скобки и `//` работают так же.
- Фигурные скобки `{...}` **зарезервированы для комментариев к вариантам**. Не используйте их внутри текста вопроса или варианта.
- Маркер `//` для общего разбора разбирается только на **верхнем уровне** — `//` внутри `{комментария}` (например, в URL) не сломает разбор.
- Секция `### Written` необязательна; дисциплины без неё просто не появятся в разделе 2.

## Генерация банка с помощью ИИ

Совсем не обязательно писать `.md` вручную. Воспользуйтесь встроенным шаблоном промпта:

1. Нажмите **📥 Импорт вопросов и теста → 📋 Скопировать промпт-шаблон**. Полный промпт окажется в буфере обмена. На русском интерфейсе копируется русская версия промпта.
2. Вставьте в конец промпта, под `=== ИСХОДНЫЙ СПИСОК ===`, сырой список тем экзамена (например, содержимое вашего `.txt`-файла со списком тем).
3. Отдайте всё это любому подходящему LLM (ChatGPT, Claude, Gemini, локальная модель — что угодно, что умеет следовать инструкциям по структуре вывода).
4. Сохраните Markdown-вывод модели как `.md`-файл (или сразу вставьте его в ExamAI через **✏️ Вставить / изменить .md**).

Шаблон промпта описывает:

- точную раскладку из двух подсекций,
- маркер `*` для правильных вариантов,
- **требование `{комментария}` к каждому варианту** — полное рассуждение, а не повтор ответа,
- то, что список `### Poll` **независим** от списка `### Written` и должен содержать **столько вопросов, сколько нужно, чтобы охватить каждую деталь** каждой темы (несколько вопросов на тему — это нормально),
- то, что строки списка `### Written` должны быть скопированы **дословно** из исходного списка тем,
- то, что после каждой темы письменного экзамена должен идти эталонный ответ `>`, который трактуется как **конспект учебника**, а не как чек-лист «один в один»,
- то, что на выходе должен быть только Markdown, ничего до и после него.

## Настройка API

Раздел 2 общается с любым совместимым с OpenAI эндпоинтом `/chat/completions` с поддержкой потоковой выдачи. Пресет по умолчанию настроен на локальный XLM Studio/LM Studio.

Откройте **⚙️ API** и заполните:

| Поле | По умолчанию | Примечания |
|---|---|---|
| **Адрес сервера (Base URL)** | `http://localhost:1234/v1` | Любой совместимый с OpenAI сервер. Приложение вызывает `<base>/models` для автоопределения модели, затем `<base>/chat/completions`. |
| **Ключ API** | *(пусто)* | Отправляется как `Authorization: Bearer <ключ>`, если задан. Оставьте пустым для LM Studio, Ollama, llama.cpp и т.п. |
| **Модель** | *(пусто)* | Оставьте пустым, чтобы использовать первую модель из `/models`. Заполните, если нужна конкретная. |

Нажмите **Сохранить**, чтобы записать значения в `localStorage`, затем **Проверить соединение**, чтобы ударить по `/models` и убедиться, что эндпоинт отвечает.

### Совместимость с OpenAI

Значения по умолчанию для разных способов запуска:

- **XLM Studio** (мой проект) — `http://localhost:1234/v1`, без ключа.
- **LM Studio** — `http://localhost:1234/v1`, без ключа.
- **Ollama** — `http://localhost:11434/v1`, без ключа.
- **Сервер llama.cpp** — `http://localhost:8080/v1`, без ключа.
- **OpenAI** — `https://api.openai.com/v1`, ключ обязателен, модель вида `gpt-4o-mini`.
- **Любой другой совместимый с OpenAI прокси** — укажите адрес и ключ соответственно.

Приложение отправляет `temperature: 0.2` и (при потоковой выдаче) `stream: true`.
